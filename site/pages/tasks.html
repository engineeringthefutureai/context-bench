What the model was asked to do

20 change requests on one synthetic shop service. For each, hidden tests and a reference solution are kept, and, for context-dependent tasks, a plausible solution written without the repository, by which the tests are failed.

Categories and tiers

Reuse
A helper that already exists in the project is needed for the change. Whether it is called by the new code is checked by a hidden reuse test. Tier 3: the helper's name is matched by the task's wording. Tier 4: it isn't, or several helpers are needed.
Convention
Tier 5. A way of doing this is established in the project (domain errors are raised, events are published, settings are read) and is defined in other files.
Cross-file
Tier 6. A feature for which coordinated edits are needed in several files: model, fulfillment and API serializer.
Control
Tiers 1-2. Everything needed is given in the task or the target file. A baseline for what is done by the model without repository context.
Trap
Something is promised by the helper's signature and docstring that is no longer done by its body. A change is counted as correct only if the helper is reused and fixed.
