Reasoning

Thinking on vs thinking off

The same 440 configurations with and without thinking. Thinking costs about 12× the output tokens (665 → 7,701 per run). What it buys is mostly answers that work at all: with thinking off a third of the runs produced no usable code or code that doesn't import. Those failures are exactly the ones a harness that runs tests would catch and could retry. The silently wrong answers, whose repo tests pass, are as common either way. Only tests that cover the behaviour catch those.

Agents

Richer tools and a self-managed working set

L7 variantPASSReuseInputCached Tool callsSeconds
grep25/2712/1222.5k7.2k1394

rich21/2712/1226.9k11.3k11127
selective24/2712/1231.4k14.3k11116

grep and hybrid: grep, file reads, references (hybrid adds semantic search). rich: the same tools, richer (search hits with source, line ranges, read a function by name). selective: rich plus drop, which removes earlier results from the conversation. On repo M the richer tools didn't help: the files are small, so reading whole files is cheap, and the model rarely used read_symbol (14 calls against 246 file reads). With thinking on, 18 of 27 selective runs dropped something, but the context saved was small: 4,734 tokens dropped and 8,670 input tokens avoided in total, about 1.0% of selective's input. Repo L (169k tokens, files and functions hundreds of lines long) is built to give these tools something to do.

Quality

Judged code quality

A blind judge (agy, rubric v2) compared all candidate patches of a task side by side, without knowing how any was made. Its correctness score agrees with the tests almost everywhere: 114 failing runs got a low score and none a high one; 307 passing runs got a high one. The 15 passing runs it scored low are where the hidden tests miss something.

Limits

How sure we are

  • One model, one sample per configuration. Repeats in the development round flipped about 1 run in 5, roughly ±3 per 13 runs of a configuration: small differences between configurations are noise.
  • One synthetic repository (two sizes) written for the experiment; real repositories are messier. Repo L, larger and older, comes next.
  • One trap task. The judge is an LLM; its scores agree with the tests but it can share the model's blind spots.
  • No level could run code. Agents with a test loop would recover some failures (see Thinking on vs off).
