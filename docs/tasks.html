What the model was asked to do

20 change requests against one made-up shop service, each with hidden tests and a reference solution. Tasks that depend on the repository's context also keep a plausible solution written without seeing the repository, which fails the tests.

Categories and tiers

Reuse
The change needs a helper that already exists in the project. A hidden reuse test checks whether the new code calls it. In tier 3 the helper's name matches the task's wording. In tier 4 it doesn't, or the change needs more than one helper.
Convention
Tier 5: the project already has an established way of doing this, such as raising domain errors, publishing events or reading settings, and it is defined in other files.
Cross-file
Tier 6: a feature that needs coordinated edits in several files at once, typically the model, fulfillment and the API serializer.
Control
Tiers 1-2: everything needed is in the task or the target file, so these tasks are the baseline for what the model does without repository context.
Trap
The helper's signature and docstring promise something its body no longer does. A change only counts as correct if the model reuses the helper and fixes it too.
